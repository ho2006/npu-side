# 研究者工作台

研究者工作台（npu-side）是跑在本机上的研究控制台。研究者用它设计一项关于「数码和智能产品购新补贴」表述方式的实验，确认研究计划后启动运行，再查看两种表述的指标差异、人群触达和关系，冻结校准协议，把问卷导入本机，并在 Intel NPU 上拟合、验证前测到后测的映射。计划、项目、实验、指标、人口和事件都由本机接口返回。浏览器负责填写、确认和展示。

当前版本是本地研究工具，面向一台研究者自己的电脑。打开工作台不需要登录。

## 给谁用

给要比较政策表述、记录实验、导出可复核材料，并检查侧端模型分数的人。

典型使用者是研究这项补贴怎么被读懂、购买意向怎么变的人。工程夹具可以先把整条路径跑通。真人问卷要另有授权记录和同意版本，工作台不会把这类数据自动当成已认证证据。

## 它回答的研究问题

默认问题是：信息清晰度会影响政策理解吗？

材料来自两项已公开的商务部政策文本，工作台内置两个版本：

| 政策编号 | 材料 |
| --- | --- |
| `cn-digital-2026-v1` | 2026 年数码和智能产品购新补贴。品类为手机、平板、智能手表（手环）、智能眼镜。 |
| `cn-digital-2025-v1` | 2025 年同题材料。品类为手机、平板、智能手表（手环），不含智能眼镜。 |

两项材料里写明的规则相同：单件销售价格不超过 6000 元，补贴为扣除各环节优惠后最终销售价格的 15%，每件最高 500 元，每人每类限 1 件。具体申领按当地实施细则执行。

每个实验把同一政策写成两种刺激，消费者被分到其中一种：

- **A0**：一段连续叙述。
- **A1**：按对象、品类、价格、计算基数、比例、上限、数量和申领方式分条列出。

问卷只问这些：适用品类、单件价格上限、补贴百分比、每件金额上限、每人每类件数、购买意向（1 到 5），以及一句原因。不确定的数值留空，不知道的品类留空列表。页面不提供检索语料，也不把研究问题发给 Qwen。

## 工作台里有什么

侧栏标题是「研究者工作台」。尚未选定实验时，对比、导出、关系图、仪表盘停在实验表单上。选定或打开某个实验之后，这四项指向该实验。主题可在浅色、深色和跟随系统之间切换，选择记在本机浏览器里。

### 实验表单

研究从这里开始。

研究者写下研究问题，并选择四项研究设置：

| 设置 | 可选值 | 作用 |
| --- | --- | --- |
| 模式 | `smoke`、`live` | `smoke` 读取本地案例计划。`live` 也在本机生成计划。两种模式都不把问题发到外部模型。 |
| 政策 | `cn-digital-2026-v1`、`cn-digital-2025-v1` | 决定使用哪一版补贴材料。 |
| 设计 | `clarity`、`factorial` | `clarity` 只比较表述清晰度。`factorial` 把表述差异记成因子效应。 |
| 暴露 | `social`、`direct` | `social` 让政策信息沿人群关系出现。`direct` 让每个人直接读到材料。 |

直接阅读和因子设计不能同时使用。选了 `direct`，设计固定为 `clarity`，因子选项不可选。选了 `factorial`，暴露固定为 `social`，直接阅读不可选。改任何一项设置，或改研究问题，已载入的计划会被清掉，确认也会取消。

计划正文包含题目、问题、假设、分析和局限。假设和局限各占一行。研究者可以改正文；一改，确认就取消，必须重新勾选「确认此研究计划」。

启动时还要填写：

- 消费者数量：10 到 60 的整数。
- 社交轮次：1 到 6 的整数。
- 随机种子：1 到 3 个互不重复的整数，范围 0 到 4294967295。

激活比例固定为 0.5，温度为 0.7。这两项随实验提交，表单上不能改。未载入计划或未确认时，「确认并启动实验」保持不可用。

确认后，工作台先保存研究项目，再创建实验并运行。运行被接口接受后，页面进入该实验的关系图。

### 关系图

关系图画出该实验的人口和边。每个人有姓名和分组。点一个节点，图下显示这个人的姓名。

一个人算作已触达，只在返回的事件里出现这两种情况时成立：动作是 `direct_exposure`，或者动作是 `feed_observed` 且带有政策帖标识。直接阅读时，每个人都有一条直接暴露事件，人群之间没有边。社交暴露时，人群连成一圈，偶数编号的人在每一轮观察到带政策帖的动态，奇数编号的人观察到空的政策帖列表。

事件一次最多取 500 条。若合计条数多于这次返回的条数，页面会写明「触达只根据返回的这些事件计算」。图上的触达就是这个窗口里的触达。

### 对比

对比页列出该实验的指标。数字来自指标接口，页面不补算缺失的差值，空单元格保持空白。

主表比较 A0 与 A1，列是指标名、A0、A1、差值、各种子差值的最小值和最大值。接口若返回了单位、因子效应、逐次运行或指标定义，页面会分别成表；没返回就不显示对应的表。

### 导出

导出页提供该实验的复现包。压缩包由实验导出接口生成，文件名为 `export.zip`，里面是三份 JSON：

- `experiment.json`：实验编号、状态、计划、配置、人口、事件、指标和占用记录。
- `surveys.json`：这次运行写下的前测和后测。
- `occupancy.json`：这次运行采到的 NPU 占用。

打开导出页只显示下载链接。真正生成压缩包发生在点击下载时。

### 导入

导入用来冻结一份校准协议，再把问卷 JSON 留在本机。校准数据不会发送给 Qwen。

基线必须是已完成的直接阅读实验。来源有两种：

- **fixture**：工程夹具。任一已完成的直接阅读实验都可以当基线。
- **human**：真人数据。基线还必须是 `live`。冻结前要填写授权记录、同意版本，并勾选授权确认。

阶段可选 `pilot` 或 `heldout`。这个阶段写在协议上，标明研究者把这份协议当作预试验还是留出检验。侧端拟合使用的切分来自每条问卷自己的 `development` / `heldout` 标记，不由这个阶段字段改写。

冻结成功后，页面给出协议编号、`protocol_sha256`，以及材料哈希和问卷哈希。可以下载空白 JSON 模板，或下载校准证据包。空白模板只含来源、三项哈希和空的 `participants`，不含问卷正文。空白模板本身不能导入：导入文件至少要有一条通过校验的参与者。

导入文件必须是 JSON，且不超过 1MiB。更大的文件不会发送。`source_kind` 必须和协议一致。导入成功后，页面显示 `result.status` 和 `result.external_validity`。

外部效度由来源决定，工作台原样展示：

- fixture：`工程夹具，不是真人证据`
- human：`待研究者审核，未自动认证`

冻结时，本机会按基线种子先写下一份校准数据。之后导入的文件成为该协议的最新问卷。侧端拟合读的是最新一份通过校验的问卷。同一页冻结过一次之后，要再冻一份协议，需要重新打开导入页。

### 仪表盘

仪表盘把一次实验的状态、指标、分群触达和侧端结果放在一起。打开页面会读取已有记录，不会自动拟合。

实验卡片显示题目、编号、状态，以及运行失败时的错误。指标和触达的读法与对比页、关系图相同。触达在这里按分组列出人数和已触达人数。

侧端需要一个协议编号。导入页冻结协议后，编号会记在本次浏览器会话里，仪表盘会带出来，也可以手改。

- 当前实验就是该协议的基线时，可以点击「拟合侧端」。拟合只针对基线。
- 当前实验不是基线时，页面说明拟合只针对基线，不在这里拟合。
- 已有拟合记录时，可以点击「验证实验」。验证用已保存的模型给当前实验打分。

拟合在 development 切分上训练，在 heldout 切分上给出 `item_brier` 和 `intention_mae`。每条算法、留出分数和按条件与种子汇总的个体分数都会列成表。页面同时显示设备、运行时、development 人数和外部效度。

任一条件下的 development 人数低于协议要求时，状态是 `INSUFFICIENT_SAMPLE`，不会写出拟合结果。验证表会标明三件事之一：与拟合记录一致、与拟合记录不一致，或这是新的实验分数。

## 一次研究怎么走

1. 打开工作台，进入实验表单。
2. 写好研究问题，选好模式、政策、设计和暴露。
3. 载入计划，改完正文后勾选确认。
4. 填好消费者数量、社交轮次和种子，启动实验。
5. 在关系图里看谁被政策信息触达，在对比里看 A0 和 A1 的差。
6. 需要留档时，下载该实验的复现包。
7. 若要做校准，先有一个已完成的直接阅读实验。真人数据还要这个基线是 `live`，并填好授权。
8. 冻结协议，导入通过校验的问卷 JSON。
9. 打开该基线实验的仪表盘，拟合侧端。再用同一协议，到其他已完成实验上做验证。

社交暴露实验可以比较表述在关系中的触达和理解。直接阅读实验是校准基线：每个人都直接读到材料，协议只能从这种已完成实验冻结。

## 指标

对比和仪表盘使用同一套指标。定义如下。

| 指标 | 含义 |
| --- | --- |
| `comprehension` | 后测答对条目的比例。条目是品类、价格上限、补贴百分比、每件上限、每人每类件数。 |
| `item_accuracy` | 与 comprehension 相同，也是后测答对条目的比例。 |
| `reach` | 被政策触达的比例。 |
| `intention` | 后测购买意向，1 到 5。 |
| `intention_change` | 后测意向减去前测意向。 |
| `item_brier` | `fit_map` 在 NPU 上的条目 Brier 分数。 |
| `intention_mae` | `fit_map` 在 NPU 上的意向绝对误差。 |
| `npu_utilization` | 本次运行采到的 Intel NPU 计算引擎占用峰值。 |

主比较是 A1 减 A0。多种子时，`seed_min` 和 `seed_max` 是各种子上这个差值的两端。因子设计会多给一行 wording 因子，指标是 comprehension 的差值。

单位行写的是这块 NPU 的名称和占用峰值。单条映射太短，引擎计数器来不及留下读数，所以运行会让 NPU 保持忙碌再采样。这个峰值是这次采样窗口里的引擎占用峰值。

逐次运行按条件和种子给出样本量、理解、条目正确率、触达、意向和意向变化。

## 侧端模型

训练在 CPU 上完成。部署推理只在本机有 Intel NPU 时执行，运行时是 OpenVINO。没有 NPU 时，推理不会执行，实验运行或侧端拟合会停在「旁侧推理未执行」，不会留下一份看起来已经完成的推理结果。

侧端同时拟合三种前测到后测的映射，并用留出样本比较它们：

- `ols`：无惩罚的线性映射。
- `ridge`：带惩罚的线性映射。
- `mlp`：小型多层网络，固定种子和训练轮数。

映射的输入是条件（A0 或 A1）、前测各条目是否答对，以及前测意向。输出是后测各条目是否答对，以及后测意向。意向在模型内部从 1–5 缩放到 0–1。

实验一启动，本机接口就会用这次运行的前测和后测做一次 `fit_map`，并把 NPU 上的条目 Brier、意向误差和占用峰值写进指标。仪表盘上的「拟合侧端」是另一步：它读校准协议里的最新问卷，用 development 拟合，用 heldout 和基线问卷做对照。验证则把已保存的模型用到研究者指定的另一份已完成实验上。

## 导入的问卷要满足什么

每份校准 JSON 要带协议要求的三项 SHA-256，以及 1 到 1000 名参与者。参与者编号形如 `p_` 加 16 到 32 位十六进制，且不能重复。

每条记录包含条件（A0 或 A1）、是否同意、是否符合资格、切分（`development` 或 `heldout`）、状态，以及前测和后测。

- 未同意、不符合资格或已撤回的人不能附带问卷答案。
- 标记为 completed 的人必须有完整的前测和后测，不能带主动跳过的字段。
- 品类只能是已标准化的选项：手机、平板、智能手表（手环）及其别名、智能眼镜、电脑、电视、其他。自由文本和身份信息不进入这份文件。
- 意向缺失时必须显式标成缺失，不能补成中立。主动跳过的字段必须为空。

## 数据留在哪里

工作台把当前实验编号和协议编号记在这次浏览器会话里。关掉这个会话后，侧栏需要重新进入某个实验才会再次记住它。主题记在本机浏览器的本地存储里。

研究记录在本机接口的目录中：实验、项目、协议，以及每次导入的问卷和回执。复现包和校准证据包都从这些本机记录打出来。

研究问题、计划正文和校准文件留在本机。`live` 只是换一种本机计划来源，标记为 `local`；`smoke` 标记为 `local-case`。两者都不把问题发给 Qwen。

## 本机怎么打开

工作台和接口是两个本机进程。

- 工作台默认在 `http://127.0.0.1:3001`。打开根地址会进入实验表单。
- 接口默认在 `http://127.0.0.1:8000`。工作台把 `/api/...` 转到这个地址。若要换一台本机接口，设置 `ECONLAB_API_URL`。

接口进程随这个仓库提供，监听本机并调用侧端训练与 NPU 推理。换地址不会把浏览器变成仿真器：社会运行、问卷生成、指标和占用仍由接口完成。

## 当前版本要按字面理解的事

随仓库运行的本机接口用随机数生成前测和后测。计划正文会写明：样本是随机数，不是调查。消费者在人口里显示为「被试」加编号。前测大约有三成五的条目按政策事实生成，后测大约有五成五；其余条目和购买意向是范围内的随机值。这是一条可重复的工程运行，用来走通设计、指标、关系图、导出、校准和 NPU 映射。它不是一次真人调查，也不是由大模型扮演的社会。

因此：

- fixture 的外部效度固定写成「工程夹具，不是真人证据」。
- human 只表示研究者声明这份文件来自真人，并提供了授权记录和同意版本。工作台把它标成「待研究者审核，未自动认证」。
- 页面只展示接口返回的数字。接口没给的差值、因子效应或运行行，页面不会补。
- 关系图的触达受事件窗口限制。窗口外的人不会被算进这次触达。
- 部署推理依赖本机 Intel NPU。没有这块设备，实验运行和侧端拟合都不会假装已经推断完成。
