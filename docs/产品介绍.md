# 研究者工作台

研究者工作台（npu-side）是跑在本机上的研究控制台。研究者把一份已经完成的社交复现包导入端侧仪表盘，在 Intel NPU 上训练五个头，然后在同一页查看占用、包里记下的指标、每位消费者的分数和人群关系。问卷、人口、事件和指标都来自这份包。浏览器负责导入、发起训练和展示。

当前版本是本地研究工具，面向一台研究者自己的电脑。打开工作台不需要登录。

## 给谁用

给已经有一份完成的社交运行、要在本机把问卷编译到 NPU 上、并对照指标和人群看分数的人。

这份包研究的是 2026 年数码和智能产品购新补贴的两种表述。工作台不重新设计实验，也不在浏览器里重跑那场社交。它读包里的记录，用这些前后测拟合前测到后测的映射。

## 包里的研究

可导入的包只有一种研究设置：

| 设置 | 必须是 |
| --- | --- |
| 模式 | `live` |
| 政策 | `cn-digital-2026-v1` |
| 设计 | `clarity` |
| 暴露 | `social` |
| 激活比例 | `0.5` |
| 温度 | `0.7` |
| 状态 | `COMPLETED` |

护照里的模式必须和这份设置一致。政策快照的编号必须是 `cn-digital-2026-v1`。直接阅读的包会被拒绝，提示「这份社交复现包不能当作直接阅读基线」。其他模式、政策、设计或暴露会提示「研究设置不在可选范围内」。

这项政策写的是：个人消费者购买手机、平板、智能手表（手环）、智能眼镜，单件销售价格不超过 6000 元，补贴为扣除各环节优惠后最终销售价格的 15%，每件最高 500 元，每人每类限 1 件。具体申领按当地实施细则执行。

同一政策有两种表述，消费者被分到其中一种：

- **A0**：一段连续叙述。
- **A1**：按对象、品类、价格、计算基数、比例、上限、数量和申领方式分条列出。

问卷记录品类、单件价格上限、补贴百分比、每件金额上限、每人每类件数，以及 1 到 5 的购买意向。包里还记下消费者人数、社交轮次和随机种子。仪表盘把这些规模原样显示出来。

## 工作台里有什么

侧栏标题是「研究者工作台」。研究分组里只有「端侧仪表盘」，地址是 `/reproductions`。打开根地址也会进入这一页。主题可在浅色、深色和跟随系统之间切换，选择记在本机浏览器里。

端侧仪表盘自上而下是六块：导入、训练、NPU 占用、指标、消费者、人口。验证做完之后，页底再出现一张验证表。

### 导入

选择一个 zip。文件超过 1MiB 时不会发送。包里每个必要文件也不能超过 1MiB。

导入成功后，这张卡片出现在列表里，并立刻打开。列表写出包的数目。还没有包时，页面写「还没有复现包。」点一行即可再打开该包。已编译的包标成「已编译」，否则是「未编译」。

同一份内容再次导入会返回原来的卡片，问卷文件保持不变。同一 `research_id` 若内容不同，会保留原来的问卷，并提示「同一 research_id 的内容不一致，已保留原来的问卷」。这个包正在训练时再次导入，会提示「这个复现包正在训练，已保留原来的问卷」。

### 训练

先选定一个包。「开始训练」按当前算法表拟合五个头，再编译、打分、采样。进度条显示 `step/total` 和当前这句话。页面大约每 0.4 秒读一次状态。

顺序是：

1. 正在拟合 OLS。
2. 正在拟合 Ridge。
3. 正在拟合 MLP。
4. 正在拟合 Neck。
5. 正在拟合 Cascade。
6. 正在 NPU 上编译。
7. 正在计算每位消费者的分数。
8. 正在采样 NPU 占用。
9. 训练完成。

尚未训练时，状态是「尚未训练」。训练中途失败时，进度停在当前步，说明是「训练没有完成。」，并带上失败原因。已经发布的侧端记录会留在原地；失败发生在发布之前时，这次的临时结果会被丢掉。

同一个包已有训练在跑时，再次点击「开始训练」会接上当前进度，不会把步数清零。磁盘上的训练记录如果对不上当前算法表，状态回到未训练，并写明「需要按当前算法表重新训练。」已有分数保留到下一次成功发布。

卡片上的一行同时说明编译和验证：

- 尚未在 NPU 上编译。
- 已编译。还没有验证。
- 已编译。验证与拟合记录一致。
- 已编译。验证与拟合记录不一致。

### NPU 占用

采样完成后，这里显示设备全名、占用峰值、引擎计数器，以及采样窗口里的推理次数。峰值保留两位小数。这个包还没有在本进程采过样时，页面写「这次进程还没有采样这个包的 NPU 占用。」

采样让 NPU 持续工作大约 4 秒，记下这个窗口里 Intel NPU 计算引擎占用的峰值。单条映射太短，计数器来不及留下读数，所以峰值来自这段采样，而不是某一条问卷行单独的耗时。

### 指标

指标来自包里的 `metrics.json`。页面不补算缺失的差值，空单元格保持空白。

主表比较 A0 与 A1，列是指标名、A0、A1、差值、各种子差值的最小值和最大值。包里若带了单位、因子效应、逐次运行或指标定义，会在同一张卡片里接着显示。没有这些内容，就不出现对应的表。

### 消费者

每一行是一对配齐的前测和后测，并带上这个人在人口里的姓名和分组。表列是姓名、分组、条件、种子、后测意向、behavior、高意向概率和 credibility。训练之前，后三列显示「尚未计算」。训练之后显示四位小数。

这些行就是拟合时用的行：

- **behavior** 读 MLP 地图的意向通道，按 1 加 4 乘以该通道的值换算，并限制在 1 到 5。
- **高意向概率** 是五个高意向头的算术平均。高意向指后测意向至少为 4。
- **credibility** 是这些头的一致程度，等于 1 减去它们的极差，并限制在 0 到 1。

### 人口

人口用三维关系图画出包里的人和边。已触达的节点是深青色，未触达的是灰色，关系连线也是深青色。点一个节点，图下显示这个人的姓名；还没点时，提示是「点击节点查看姓名。」卡片标题下写出触达人数和总人数。

一个人算作已触达，只在包里的事件出现这两种情况时成立：动作是 `direct_exposure`，或者动作是 `feed_observed` 且带有政策帖标识。若记录的合计条数多于事件列表，页面会写明触达只根据这些事件计算。

### 验证

「验证」在已经编译之后可用。它把保存的模型重新编译到 NPU，用包里的问卷再打一次分，并和拟合时留下的分数比较。问卷和占用记录都不会被改写。

验证表按条件和种子列出每个头的 `item_brier` 与 `intention_mae`。说明是三者之一：与拟合记录一致、与拟合记录不一致，或还没有验证记录。尚未编译就点验证，会提示「尚未在 NPU 上编译。」

## 一次使用怎么走

1. 打开工作台。根地址进入端侧仪表盘。
2. 导入一份已经完成的社交复现包。
3. 确认卡片上的模式、设计、暴露、政策和规模。
4. 开始训练，等到进度写「训练完成。」
5. 看占用峰值、A0 与 A1 的指标、消费者分数和人口触达。
6. 需要复核时，点验证，看新分数是否与拟合记录一致。

## 复现包里要有什么

zip 里要有这八个文件：

| 文件 | 内容 |
| --- | --- |
| `passport.json` | 研究编号、完成状态、模式。编号是带连字符的 UUID。 |
| `config.json` | 上面那张研究设置，以及政策快照。 |
| `plan.json` | 至少要有非空的研究题目。仪表盘用这个题目当卡片标题。 |
| `surveys.json` | 前测和后测。至少要能配成两对。 |
| `population.json` | 每个人有编号、姓名、分组、年龄和预算。 |
| `network.json` | 人与人之间的边。边的两端必须都在人口里。 |
| `events.jsonl` | 一行一个事件。 |
| `metrics.json` | 至少要有 `comparison` 数组。 |

问卷里一条可用记录要有条件 `A0` 或 `A1`、阶段 `pre` 或 `post`、种子、被试编号，以及后测里 1 到 5 的意向。同一个人的前测和后测都在，并且能在人口里找到，才会出现在消费者表里。

## 五个头

拟合在 CPU 上完成。地图和高意向头都编译到 Intel NPU，运行时是 OpenVINO。高意向头只在打分时留在内存里，打完就丢掉。地图的中间表示会留下来，供以后验证重新编译。没有 NPU 时，编译不会执行，训练停在失败，已发布的侧端结果保持原样。

每个头有两套输出。地图把前测映到后测：五道条目是否答对，加上意向。高意向头判断后测意向是否至少为 4。输入是条件（A0 为 0，A1 为 1）、前测各条目是否答对，以及前测意向。意向在模型内部从 1–5 缩放到 0–1。

| 头 | 做法 |
| --- | --- |
| OLS | 闭式线性映射，惩罚为 0。地图是 7 到 6，再接 sigmoid。高意向头是 7 到 1，再接 sigmoid。 |
| Ridge | 同样的闭式映射，惩罚为 1。惩罚加在七个斜率上，截距保持在未惩罚的中心。 |
| MLP | 训练 30 轮，种子 42。地图宽度 7-16-6，中间有 ReLU。高意向头宽度 7-8-1，中间有 ReLU。 |
| Neck | 同样训练 30 轮。地图和高意向头的隐藏宽度都是 2，中间有 ReLU。 |
| Cascade | 地图是 7 到 6 的 sigmoid，再接到 6 到 6 的 sigmoid。高意向头隐藏宽度 4，两段都是线性加 sigmoid，没有 ReLU。 |

地图的条目通道用二元交叉熵，意向通道用均方误差。高意向头用二元交叉熵，标签在后测意向达到 4 时为 1。

## 数据留在哪里

每个包存在本机接口目录的 `reproductions/{research_id}/` 下。这里有卡片、问卷、人口、事件、指标和政策快照。训练发布之后，`side/` 里有训练状态、编译记录、每个头的模型和消费者分数。验证结果写在 `side/check.json`。占用写在该包的 `occupancy.json`。

问卷在导入之后保持不变。训练和验证都不改写 `surveys.json`。

每次接口请求会在本机 `access/` 目录留下一条记录，包括方法、路径、状态和耗时。成功的请求不保留错误说明。

主题记在本机浏览器里。工作台不把当前包编号写进会话存储；要看哪个包，就在列表里点它。

## 本机怎么打开

工作台和接口是两个本机进程。

- 工作台默认在 `http://127.0.0.1:3001`。打开根地址会进入端侧仪表盘。
- 接口默认在 `http://127.0.0.1:8000`。工作台把 `/api/...` 转到这个地址。若要换一台本机接口，设置 `ECONLAB_API_URL`。

接口进程随这个仓库提供。它保存复现包，并调用侧端拟合与 NPU 编译。换地址不会把浏览器变成仿真器：指标、人口、事件和问卷仍来自导入的包，训练仍由接口完成。

## 当前版本要按字面理解的事

工作台接受的是一场已经完成的 live 社交运行，设计是 clarity，政策是 2026 年购新补贴。它不在这里生成计划，也不用随机数另造一份问卷。

因此：

- 指标、触达和后测意向都是包里已经写下的记录。页面只展示这些记录，以及训练之后新算出的消费者分数。
- 直接阅读、其他政策版本和其他设计不能导入。
- 同一研究编号的另一份内容不会覆盖已保存的问卷。
- 部署编译和验证依赖本机 Intel NPU。没有这块设备，训练会失败，不会留下一份看起来已经编译完成的新结果。
- 占用峰值是大约 4 秒采样窗口里的引擎占用峰值。
